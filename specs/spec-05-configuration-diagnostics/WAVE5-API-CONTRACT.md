# SPEC-05 — Contratos web de Wave 5

Fecha: 2026-11-27. Estas rutas son aditivas en la API administrativa GEOPS. Requieren cookie de sesión; no aceptan identidad técnica de dispositivo como sesión administrativa. Solo usan PostgreSQL y contratos Wave 2/3; no ejecutan escrituras ManageEngine. Las rutas devuelven errores sanitizados `{error:{code,message,request_id}}`.

| GET | Requisito | Respuesta |
| --- | --- | --- |
| `/v1/admin/mdm/workspace/summary` | `mdm.diagnostics.view`; `gps_data_tenant_access` y `gps_health_tenant_access` para cada tenant visible | `as_of`, `source`, `registered`, `linked`, `unlinked`, `no_data`, `stale`, `offline`, `permission`, `battery`, `capture`, `transmission`, `configuration`, `pending`, `no_findings`; `compliance:null` y razón hasta verificar tenant. |
| `/v1/admin/mdm/workspace/devices` | Mismo alcance | `{as_of,page,limit,total,items}`. Incluye dispositivos registrados sin snapshot. Cada elemento contiene identidad GEOPS, agente, tenant autorizado, ownership, instalación, vínculo MDM, modelo, Android, APK, tiempos, permisos, ejecución, GPS, hallazgos, banderas y correcciones pendientes. |
| `/v1/admin/mdm/workspace/devices/:id/timeline` | Mismo alcance; el detalle se autoriza en backend | `{device_id,from,to,truncated,unavailable,items}`. Cada evento tiene `at,type,label,source,evidence_ref`. Eventos administrativos y de corrección exigen además `mdm.audit.view`. |
| `/v1/admin/mdm/workspace/report` | `mdm.diagnostics.export` **y** alcance de diagnóstico/tenant; historial de correcciones solo con `mdm.audit.view` | JSON sanitizado `{generated_at,source,scope,mdm_applied_evidence,corrections,corrections_truncated,items}`. Máximo 100 equipos y 500 solicitudes por petición; `corrections:null` sin permiso de auditoría. |

Filtros combinables para listado y reporte: `q` (nombre, UUID o agente; máximo 80), `issue` (`unlinked`, `permission`, `battery`, `capture`, `transmission`, `offline`, `stale`, `no_data`, `configuration`, `pending`, `no_findings`), `severity` (`CONFIRMED`, `POSSIBLE`, `STALE`, `OFFLINE`, `UNKNOWN`), `android`, `app`, `mdm` (`valid`, `unverified`), `age` (`fresh`, `stale`, `none`), `ownership` (`CORPORATE_MANAGED`, `PERSONAL_BYOD`, `UNVERIFIED`), `sort` (`name`, `contact`, `diagnosis`, `android`, `app`), `direction` (`asc`, `desc`), `page` (1–1000), `limit` (1–100), `ids` (hasta 100 UUID separados por coma). Valores no reconocidos devuelven 422. La búsqueda y paginación se ejecutan en SQL con desempate por UUID. Una página vacía fuera del rango conserva el total mediante una consulta agregada de respaldo.

Timeline admite `from`, `to` ISO y `kind` (`ALL`, `DIAGNOSTIC`, `GPS`, `PERMISSION`, `CONFIGURATION`, `REMEDIATION`, `ADMIN`), con rango máximo de 30 días. `truncated` advierte si el historial de snapshots alcanza 100. No atribuye como observación el inicio exacto del FGS, intento de envío, reinicio ni cambio de perfil MDM: el snapshot v1 carece de esos timestamps. El portal los muestra como no disponibles. Cambios entre snapshots son observaciones comparativas, no auditoría histórica del sistema operativo.

El listado usa una proyección SQL única con joins laterales para último snapshot, último contacto y correcciones pendientes. `geops_device_tenant` y `mdm_binding` son candidatos de propiedad; solo se incluye un equipo con exactamente un tenant **autorizado** para ese administrador. `mdm_inventory_device.customer_id` es el cliente del proveedor, no la clave de tenant GEOPS; el vínculo se comprueba por `geops_device_id`, ID numérico, estado managed y no retirado. El detalle sigue sujeto al `DeviceDiagnosticsService.latest` y a las verificaciones de Wave 3.

Los reportes incluyen solo valores tipados/permitidos del snapshot y referencias de solicitud. No incluyen posición histórica, token, cookie, contraseña, secreto OAuth, razón libre de corrección ni payload completo del proveedor. Las lecturas y exportaciones registran `audit_event`. Los endpoints `POST /v1/admin/mdm/remediations/preview` y `/requests` conservan Origin/CSRF, login reciente, idempotencia y RBAC. `POST /requests/:id/submit` conserva `503 mdm_write_disabled`.
